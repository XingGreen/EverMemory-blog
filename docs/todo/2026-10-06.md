## P2 · 登录相关改进（可与 P1 一起做）

### 2. 429 前端尚未消费 `retryAfterSeconds`，只有倒计时

`VerifyScreen.svelte` 目前在 429 时禁用按钮 + 倒计时展示，但**没有**据此拦截正在飞行中的重复提交。已在 `handleKeyDown` 里加了 `lockoutSeconds <= 0` 判断，`<button>` 也有 `disabled`，但 `handleSubmit` 本身没有入口防护。风险低，可后置。

### 3. `login-guard` 的「读—改—写」在多实例下会丢计数

`CLAUDE.md` 与 `login-guard.ts` 头部注释均已记录。KV 最终一致导致并发失败可能互相覆盖。彻底解法是改用原子操作（CF Durable Objects 的 `checkLimit`，或 KV 的 conditional write），但那要绑定特定运行时——与「不支持 CF 部署」的结论冲突，所以暂列为 P2 且**不阻塞**。

### 4. Turnstile 未做 per-sitekey 的 rate limit 调优

窗口固定为 60 秒 / 10 次（`src/utils/login-guard.ts` 的 `ATTEMPT_WINDOW_SECONDS` / `ATTEMPT_LIMIT`），无环境变量开关。真实部署若误伤，可考虑加 `ADMIN_LOGIN_ATTEMPT_LIMIT` 之类的覆盖。注意：这类「看起来该做成配置」的旋钮不要一次加太多，先看是否真的有人调。
