# Accessibility & Keyboard Rules

Full-form rules for keyboard, focus, contrast, and motion across the public theme and
`/admin/`. Framework borrowed from the reference project's `rules/a11y.md`; every requirement
below is verified against this repository's own components, not copied from its component
inventory. Gate: WCAG 2.1 AA by manual walkthrough — this project has no axe/Playwright a11y
suite, so screenshots alone are not acceptance for interactive changes.

## 1. Semantics and ARIA

- Prefer native elements over ARIA re-creations: actions are `<button>`, navigation is
  `<a href>`, dialogs are a real overlay element with `role="dialog"` + `aria-modal="true"`
  (see `ConfirmDialog.svelte`, `DeleteConfirmModal.svelte`, `DraftConflictDialog.svelte`).
- Every control has an accessible name: visible text when present; `aria-label` for icon-only
  controls (the eye toggle in `SecretFields.svelte`, the sidebar collapse button). Form fields
  get `aria-label` or an associated `<label>` — never a placeholder as the only label.
- State is exposed, not just painted: `aria-expanded` on disclosure buttons (the savebar diff
  toggle), `aria-current`/`aria-selected` where tabs or pagination exist,
  `aria-hidden="true"` on decorative icons.
- Collapsed non-interactive content must not stay focusable: use `hidden`, `inert`, or remove
  it from the tree. A collapsed panel whose buttons are still tabbable is a defect.

## 2. Keyboard interaction

- Native controls keep their native keyboard semantics; do not intercept Enter/Space on real
  buttons or inputs.
- Self-drawn controls must supply what they took away: Tab order, arrow-key movement for
  option lists, Esc to dismiss overlays and menus.
- Every dialog closes on Esc; every popover/menu closes on Esc and outside click. If a
  component grows a second close path, both paths work.

## 3. Focus management

- Opening a dialog or drawer moves focus into it (first field or the dialog container).
- Modal surfaces trap Tab while open. Not yet implemented anywhere — treat it as the required
  behaviour for new modal code and retrofit opportunistically when a dialog is touched.
- Closing returns focus to the element that opened the surface.
- All interactive styles use `:focus-visible` (already the norm in `ui-base.css` and admin
  components); never remove the outline without replacing it.

## 4. Contrast

- Body and small text (below 18.66px, or bold below 24px): ≥ 4.5:1.
- Large text: ≥ 3:1. Icons and UI borders that carry meaning: ≥ 3:1.
- Colors come from tokens (`--deep-text`, `--content-meta`, `--primary`, `--destructive`); no
  hardcoded hex in component styles. Meta-grey text (`--content-meta`) must stay readable in
  both themes — if a value fails contrast, fix the token, not the call site.

## 5. Dark mode

- Both themes must pass everything above. Colors resolve through tokens that switch under
  `.dark`; a component that works only on light backgrounds is broken.
- Screenshots for acceptance include dark mode whenever the change affects shared surfaces.

## 6. Motion

- Respect `prefers-reduced-motion`: transitions and animations collapse to (near) zero
  duration; JS-driven animation jumps to the end state. Precedent: the `field-breathe` flash
  in `SecretFields.svelte` ships a reduce branch — new animation follows the same shape.
- Response animations (expand, confirm, step change) may exist; ambient looping animation on
  the user's behalf may not.

## 7. Admin-specific traps

- Overlays inside `.admin-content` must portal to `document.body`: that subtree applies a
  `zoom`, so `position: fixed` offsets get scaled a second time and land in the wrong place.
  Move `--md-*` variables and font sizing onto the portalled node itself.
- After any DOM-structure change, re-verify keyboard order — the zoom container and portals
  can reorder visual and DOM order independently.

## 8. Verification

- Interactive changes: walk the flow with keyboard only (Tab in, operate, Esc out), then take
  screenshots for acceptance.
- Dialog/menu changes: verify open-focus, Esc, outside-click, and focus return, in both
  themes.
- `astro check` does not parse CSS or validate ARIA; a passing type check is not a11y proof.
